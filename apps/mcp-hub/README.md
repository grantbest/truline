# mcp-hub

The capability gateway. One FastAPI service that exposes the store, the factory and the LifeOps
vertical as REST/OpenAPI (`/api/v1/…`) and as MCP tools, behind one identity contract. It is
the only thing that holds the substrate API key; browsers and agents talk to it, never to the
store.

## The identity contract

Every request is resolved to an identity (`src/access_auth.py`) and every capability declares the
scope it checks. `MCP_HUB_IDENTITY_MODE` sets how far that goes:

| Mode | Behaviour | Use |
|---|---|---|
| `enforce` | a Cloudflare Access assertion is verified against the team's JWKS; headers without an assertion are rejected | production |
| `log-only` (default) | the same verification, but a failure is logged and the request continues with whatever identity it carries; a request with no identity at all is still refused at the scope check | rollout |
| `trust-headers` | `X-Truline-Client`, `X-Truline-Client-Type`, `X-Truline-Scopes`, `X-Truline-Email` are taken as given, never verified | a trusted proxy in front, or the quickstart |

Every request logs one `mcp_hub_request` line with the client, scopes, capability, the scope
checked, the verdict and the outcome. That line is the audit.

## Surfaces

- `GET /health`
- `/api/v1/factory/…` filing and probing `dev.task` beads, the dispatcher's status
- `/substrate/{path}` a raw passthrough to the store for identities holding `substrate.proxy`
  (humans, scopes `*`); the console's only route to data
- `/mcp` the MCP endpoint; `openapi.json` is the REST surface, regenerated by CI
- `/webhooks/plaid` for the LifeOps vertical

## Run it

```bash
export SUBSTRATE_URL=http://127.0.0.1:8000
export SUBSTRATE_API_KEY=local-dev-key
export MCP_HUB_IDENTITY_MODE=trust-headers      # local only
uv pip install -e .
uvicorn openapi_app:app --app-dir src --port 8001
curl localhost:8001/health
curl "localhost:8001/substrate/beads?namespace=dev" \
  -H 'X-Truline-Client: me' -H 'X-Truline-Client-Type: human' -H 'X-Truline-Scopes: *'
```

The image is built from the repository root (`docker build -f apps/mcp-hub/Dockerfile .`)
because it carries the dispatcher's filing path and the substrate client alongside its own
source; the root `.dockerignore` is the whitelist.

## Environment

| Var | Required | Notes |
|---|---|---|
| `SUBSTRATE_URL`, `SUBSTRATE_API_KEY` | yes | the store and its write key |
| `MCP_HUB_IDENTITY_MODE` | no | `enforce`, `log-only` (default), `trust-headers` |
| `CLOUDFLARE_ACCESS_TEAM_DOMAIN`, `CLOUDFLARE_ACCESS_AUDS` | in `enforce` and `log-only` | the issuer and accepted audiences |
| `CLOUDFLARE_ACCESS_SERVICE_TOKEN_NAMES`, `CLOUDFLARE_ACCESS_CLIENT_SCOPES` | no | machine identities and their scopes |
| `MCP_HUB_PUBLIC_URL`, `LIFEOPS_CONSOLE_PUBLIC_URL` | yes in production | what the service says about itself |
| `TEMPORAL_ADDRESS`, `TEMPORAL_NAMESPACE`, `TEMPORAL_TASK_QUEUE` | for the worker | `src/temporal_worker.py`, a separate process |
